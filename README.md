# Hand Over

واجهة تسليم المناوبات مبنية باستخدام Next.js App Router وTypeScript، مع مصادقة Supabase وجداول Postgres للأحداث والتحديثات.

## التشغيل المحلي

1. ثبّت Node.js 20.9 أو أحدث.
2. انسخ `.env.example` إلى `.env.local`، ثم أضف عنوان مشروع Supabase ومفتاحه العام (publishable key). لا تضف `service_role` إلى الواجهة أو إلى هذا الملف.
3. شغّل `npm ci` ثم `npm run dev` وافتح `http://localhost:3000`.
4. راجع مخطط قاعدة البيانات أولًا، وخذ نسخة احتياطية قبل أي ترحيل. ملف `supabase/migrations/202610110001_handover_auth_and_events.sql` يرفض التنفيذ إذا وجد جداول Hand Over بالاسم نفسه؛ لا تطبّقه على قاعدة إنتاج قبل التأكد من حالتها.

## مصادقة Supabase

- إنشاء الحساب وتسجيل الدخول بالبريد وكلمة المرور، والجلسة محفوظة في cookies عبر `@supabase/ssr`.
- التسجيل مفتوح لأي بريد وفق قرار مالك المشروع. يمكن تفعيل تأكيد البريد من إعدادات Supabase.
- أضف إلى إعدادات Redirect URLs في Supabase مسار `/auth/callback` على نطاق التطوير ونطاق Vercel.
- الصفحات والـ API تتحقق من المستخدم عبر الخادم. سياسات RLS تمنع الوصول لغير المسجلين، وتسمح فقط لمنشئ الحدث بتعديله أو حذفه.
- يمكن لجميع الحسابات المسجلة مشاهدة الأحداث وإضافة تحديثات للخط الزمني؛ الإنشاء والتعديل والحذف متاحة لمنشئ الحدث.

## إعداد Vercel

أضف المتغيرين التاليين من إعدادات المشروع في Vercel لكل بيئة مستخدمة، ثم أعد النشر:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`

المفتاح العام مصمم للاستخدام من المتصفح، وتُحكم عملياته بسياسات RLS. لا تضف مفاتيح `service_role` أو كلمات مرور إلى المستودع.

## البيانات السابقة

الإصدار السابق كان يحفظ بيانات تجريبية في `localStorage` في متصفح كل مستخدم. هذا الإصدار لا يحذفها، لكنه لا يرفعها تلقائيًا إلى Supabase لأن هوية منشئ كل سجل قديمة وغير موثقة. أي استيراد لاحق يحتاج مراجعة البيانات وتحديد طريقة إسناد المنشئ أولًا.

## فحوصات المشروع

- `npm run typecheck`
- `npm run build`

لا يوجد حاليًا إطار اختبارات آلية لتدفقات المصادقة أو قاعدة البيانات؛ وتحتاج اختبارات التكامل إلى مشروع Supabase إعداداته منفصلة عن الإنتاج.
